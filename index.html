The catalogue

02 · Quick start

Use it in a minute

Fetch

From the command line

Plain static files. No key, no rate limit.

curl https://open.divekit.app/datasets/certifications.json

Validate

Against its schema

Each dataset names its schema in $schema.

npx ajv validate \
  -s https://open.divekit.app/schemas/certifications/dive-certifications.schema.v1.0.0.json \
  -d certifications.json

Build

In your app

Served with CORS by GitHub Pages, so a browser can read it too.

const res = await fetch(
  'https://open.divekit.app/datasets/cylinders.json'
);
const { cylinders } = await res.json();

04 · References

Where the numbers come from

References

references.json lists the papers, books, standards, manuals, articles and videos behind Dive Kit's calculators and guide. Each record says what the source is authoritative for, so an assistant can cite it.

Search sources

search-sources.json lists where to search next when no reference answers a question, in the order to try them. vetted says whether what you find there can be cited as trustworthy.

How Dive Kit uses them

The Dive Kit MCP server's lookup_references tool searches the references. When nothing matches, it returns the search sources, so the assistant knows where to look next and says the result is not Dive Kit-vetted.

Both files are meant to grow with contributions. See Adding a reference.

05 · Contribute

Fix a record, add a dataset

We welcome:

  • New or corrected certification data
  • Updated equivalencies or limits
  • Additional recognised agencies
  • New references and search sources
  • Translations, metadata and documentation
Contributing guide Discussions

Validate locally before you open a pull request. CI runs the same checks on every PR.

./scripts/validate.sh
# ✓ schemas are valid JSON Schema
# ✓ each dataset matches its schema
# ✓ no duplicate ids

Needs Bun (or Node.js) and jq. Datasets and schemas are versioned semantically; a breaking change bumps the major version.
